Provider logic is isolated under `internal/llm` for OpenAI, Anthropic, Ollama, and OpenAI-compatible transports. Routing goes through `internal/service/provider_adapter.go` and shared contracts/normalization/streaming packages.

Normalized requests and selection:
- OpenVibely is converging all model-call behavior on a normalized provider request pipeline. Lifecycle preparation precedes request construction; selected memory/skills, task metadata, goals, follow-up data, attachments, and runtime tools become one `AgentRequest` rather than being reinterpreted by each adapter.
- `AgentRequest.Followup=true` is authoritative even with empty history. OpenAI, OpenAI-compatible, Anthropic, Ollama, and mixtures route zero-history follow-ups through Chat streaming while preserving follow-up prompt and `ChatSystemContext`. Initial worker tasks carry selected-memory context through `ProjectInstructions`; Chat/API follow-ups use `ChatSystemContext`.
- Direct utility calls such as architect, backlog, collision, insights, trend, and upcoming are direct-style model calls and do not run task/chat memory lifecycle unless deliberately redesigned. `OperationDirect` is a lifecycle hook step, not a coding turn; preserve the hook Agent prompt and omit shared coding-agent framing.
- Provider selection uses `LLMConfig.Provider`, `Model`, and `AuthMethod`, not model string alone. Normal task starts choose current `Task.AgentID`, then project default, then global default. Stored per-run/queued model IDs are history/accounting evidence, not immutable rerun assignment.
- Chat uses explicit `agent_id` when supplied; empty/`auto` uses complexity/vision routing, and browser `default` resolves project default before global default. Queued Chat inputs preserve the effective model ID. `Task.AgentDefinitionID` selects persona/system prompt/skills; task `agent_id` selects provider/model. Actual per-run model identity is stored but not shown in task-thread history (`#128`).
- Vision routing uses compact semantic rows with model identity/tier/default/provider/auth metadata and credential-presence flags, hydrating only the selected config. No-image/already-capable paths remain query-free. Regression coverage must protect secret exclusion, tier/default eligibility, empty-store `ANTHROPIC_API_KEY` fallback, and selected-model delivery.
- Runtime task creation uses compact model rows (`ID`, `Name`, `Provider`, `Model`, `IsDefault`, `AutoStartTasks`) and hydrates full configs only at provider execution. API Chat follows the same compact-selection pattern.
- Model names/slugs are trimmed and validated; blank runnable values and case-insensitive duplicate names are rejected. Mixture is a virtual provider with its own stable identifier. CLI auth for OpenAI/Anthropic is retired; migrations normalize legacy rows and adapters reject `auth_method=cli`.

First-party providers:
- OpenAI supports Responses and Completions APIs. Responses `SendAgentic` performs Codex-style client-side history compaction for API-key and OAuth. GPT-6 Astra and GPT-5.6 Sol/Terra/Luna are supported; unknown nonblank first-party selections default to `gpt-5.6-sol`, while blank runnable values remain invalid. Astra supports `low` through `max` reasoning but not `none`, uses its 1.05M context metadata for compaction, and can use provider-native web search. Astra does not support configurable temperature, so its UI control is hidden and browser-form normalization clears submitted or stale values. Fast mode is not persisted/requested (`#295`); GPT-5.6 Cyber/Daybreak aliases remain gaps (`#602`, `#609`), and `gpt-5.3-codex` needs a bounded support audit.
- Responses Lite WebSocket state is conversation-, credential-, and account-scoped rather than global. It serializes compatible turns using `previous_response_id`, reconnects stale sockets once, then falls back to HTTP.
- Anthropic uses `ProviderAnthropic` and `pkg/anthropicclient` for API-key/OAuth calls. Supported IDs include Claude Opus 5, Sonnet 5, Haiku 4.5, Fable 5, and Mythos 5. Fable/Mythos stay selectable but are not recommended defaults; adaptive thinking is required and HTTP 200 refusals surface as unsuccessful results. Opus 4.1 is retired. OAuth/API-key refresh is reactive, not background scheduled.
- Anthropic `invalid_grant` refresh failures permanently mark `oauth_needs_reauth` until a successful refresh clears it.
- `ProviderOpenAICompatible` is a generic Chat Completions path for `/chat/completions`, separate from Ollama. It supports API-key or optional missing auth for local servers, base URL/transport/presets, streaming, provider tool calls/results, usage normalization, and extra header/body JSON. Protected fields such as `model`, `messages`, `stream`, and tools cannot be overridden by extra body values.
- Presets cover hosted gateways and local vLLM/LM Studio/SGLang/LiteLLM-style servers plus Custom OpenAI-Compatible; Ollama remains separate, uses `/api/chat`, defaults to `http://localhost:11434`, and accepts arbitrary exact custom model names. OpenAI-compatible discovery is best-effort through `/models/openai-compatible/available` with credentials in headers, and there is intentionally no manual Discover button. Unverified providers such as xAI, GitHub Copilot, native Bedrock/Gemini, and MiniMax are not surfaced without an explicit decision.
- Z.AI `GLM-5.3-Flash` support is incomplete (`#911`): preset/model fallback, image capability, function calling, 1M context, and required thinking controls are not fully represented. Ollama runtime tools remain unsupported (`#264`). Chat endpoint visibility for compatible/Ollama configs is an open prompt-safe UI gap (`#808`).

Mixtures and OAuth:
- `ProviderMixture` is a virtual `agent_configs` row with `mixture_config_json`. It fans out ordered non-mixture reference calls, appends private outputs only to the aggregator context, and streams only the aggregator's user-visible response. References receive no tools, normal coding prompts, task mutation context, or public output; the aggregator retains normal authorized tools. Compact `mixture_progress` events use the existing live channel.
- `LLMConfig.IsCallableMixtureSlot` rejects recursive, duplicate, missing, retired-CLI, hidden/internal/unknown, and non-callable rows. Mixture CRUD blocks invalid slots and deletion of referenced models; Ollama aggregators receive no inherited runtime tools or textual fallback.
- OAuth tokens currently live per `agent_configs` row, preserving per-row freshness/reauth state. Editing in place preserves tokens unless provider/auth changes require clearing them. Long-term direction is a provider-account token table once reliable Anthropic account identity exists.
- Provider 401 recovery reloads from DB and may persist rotated tokens; it does not reread disk/keychain/environment material. Built-in callbacks consume pending state once and write only when provider, OAuth method, target, and config revision match. Missing/blank access tokens fail before mutation; zero-row updates fail. Chat model cards expose OAuth status, but Chat readouts do not yet (`#695`).

Tools, retries, and streaming:
- Provider-native web search/fetch is provider-executed (`web_search`, versioned Anthropic raw-tool types), not local web tooling. Runtime tools are request-scoped and provider-generic with read/write classification. Tool-capable transports are OpenAI API/OAuth, Anthropic API/OAuth, and OpenAI-compatible API-key Chat Completions; unsupported paths receive neither unusable definitions nor marker fallbacks.
- Shared runtime policy owns plan mode, orchestration chat, task follow-ups, defaults/filters, and `SkipDefaultTools`; adapters retain provider schema/naming and local read-only grants. Memory tools are request/tool-profile decisions, not global adapter defaults. Anthropic wire aliases canonical `skills_list` to avoid collisions with `skill_view`/`skill_manage`.
- A request-scoped guard turns an identical exhausted-empty `list_tasks` retry into a `duplicate_noop` response with guidance; different parameters, mutations, errors, nonempty, or pageable results clear it. `read_file` returns `decimalLineNumber<TAB><source bytes>` so indentation remains exact. Scoped file tools select the longest configured scope prefix and preserve fallback, permissions, traversal, and symlink containment.
- Provider-local file/shell execution is centralized in `pkg/agenttools`; provider packages retain schemas and thin wrappers. Bash timeout policy is explicit: Anthropic defaults to ten minutes only without a positive timeout; OpenAI passes its configured policy.
- External HTTP retry policy is centralized in `internal/httpretry`. Streaming logical-turn retries reconstruct canonical requests, honor cancellation/backoff/Retry-After, and append visible output unless a caller explicitly resets it. Primary client and after-complete deadlines default to ten minutes. Hidden-thinking/tool-argument deltas reset inactivity; known streaming timeout gaps are `#54` and `#68`.
