OpenVibely has a large Go suite. Durable quality work emphasizes broad behavioral coverage and production-shaped performance evidence rather than narrow happy paths, raw logs, or task-by-task benchmark notes.

Coverage and fixtures:
- `internal/service` and `internal/handler` are the broadest seams, especially error, pagination, webhook, retry, scheduling, channel, and orchestration paths. `internal/service/llm_service.go` needs controlled caller mocks to avoid flaky tests.
- `NewTestDB` uses isolated in-memory fixtures from an immutable serialized SQLite template with UTC, foreign keys, busy timeout, one connection, migrated schema, seed data, cleanup, and default-agent behavior. Avoid blanket `t.Parallel()` with shared DB setup.
- Generated `*_templ.go` is excluded from coverage summaries while template tests still run. Prefer behavior over granular tests around already-covered code.
- Runtime/action tests cover ownership, authorization, pagination, mode restrictions, malformed JSON, provider-tool-incapable paths, and case-insensitive JSON-field presence. Explicit numeric zero must be tested as supplied invalid input rather than omission.
- Production-shaped regressions must enter through real service/repository/router boundaries. Synthetic mutations or manually dispatched events do not prove claims, broadcaster transport, listeners, project isolation, or authoritative refresh.
- System-agent control regressions enter through the real handler, service, repository, and lifecycle boundaries. Coverage includes enabled/model persistence, protected Goal Agent disable rejection, UI hydration and locked controls, startup reconciliation preserving user-managed choices, disabled-agent hook filtering, lifecycle hydration of configured model IDs, and Skill/Memory maintenance schedule synchronization. - Breadcrumb selector coverage proves project/schedule/Chat scope, current-first behavior, exact/prefix/contains relevance ordering, bounded boundary pages, an executable empty-search plan using the discovery index without a temporary sort, and visibility changes after task update/delete. Production-shaped benchmark coverage compares compact selector retrieval with full task hydration across representative cardinalities and validates bounded query work.

Validation conventions:
- Prefer `make test`, `make test-cover`, or targeted `go test` with `-count=1 -timeout 120s`; use readiness polling instead of fixed sleeps and `testing.Short()` for timing-sensitive cases. Full repository validation uses CI-style `-timeout 240s`; `internal/handler` can exceed 120 seconds under combined load while passing in isolation.
- Use `go test -race` only for a concrete race-sensitive invariant changed in production or an explicit requirement, and keep it to the smallest deterministic regression. Do not run performance/allocation gates under the detector.
- The primary Actions coverage/compile gate is `OPENVIBELY_SKIP_BROWSER_PERF=1 go test ./... -count=1 -timeout 240s -coverpkg=./... -coverprofile=coverage.txt`, including `cmd/server`. Codecov acceptance uses hosted `line_coverage` for the exact commit.
- Preserve generated-file cleanliness, templ coverage exclusions, packaged-update native/E2E matrices, Linux cache identity/action pins, untrusted-cache handling, setup timing artifacts, and Windows rollback-helper cleanup.
