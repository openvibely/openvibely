OpenVibely has a large Go test suite. Durable quality work should emphasize broad behavioral coverage and production-shaped performance evidence rather than narrow happy paths, raw logs, or task-by-task benchmark notes.

Coverage direction:
- `internal/service` and `internal/handler` are the broadest coverage seams, especially error, pagination, webhook, retry, scheduling, channel, and orchestration paths. `internal/service/llm_service.go` needs controlled LLM caller mocks to avoid flaky tests.
- Generated templ `*_templ.go` files are excluded from coverage summaries while template tests still run. Prefer broad behavioral coverage over granular tests around already-covered code, and avoid blanket `t.Parallel()` around shared database setup.
- Codecov acceptance uses hosted `line_coverage` for the exact commit; local profile percentages or configuration workarounds are insufficient.
- `NewTestDB` creates isolated in-memory fixtures from an immutable serialized SQLite template with UTC, foreign keys, busy timeout, `MaxOpenConns(1)`, migrated schema, seed data, cleanup, and default-agent behavior.
- Runtime-tool/action tests should cover ownership, authorization, pagination, mode restrictions, malformed JSON, and provider-tool-incapable paths. Numeric JSON presence tests must include case-insensitive field keys and prove explicit zero values fail before provider calls.
- Browser task-goal route coverage verifies explicit and selected-project ownership for GET, set, pause, resume, and clear; known tasks without either project context are rejected before goal reads or mutations, unknown tasks remain not found, and foreign tasks are rejected without goal leakage or mutation. Same-project JSON and HTMX flows remain successful.

Performance contracts:
- File-backed production SQLite now uses the measured dedicated `1W + 1R` layout: one writer pool connection and one query-only reader connection; `:memory:` fixtures stay single-connection. The disposable benchmark matrix compared shared pools `1/2/4/8` with dedicated `1W+1R`, `1W+2R`, and `1W+4R` at active workloads `1/4/10`, using real task/history reads, task and Automation claims, 500 ms execution-output flushes, WAL reader pressure, and pool/busy/WAL metrics. Duration-based samples selected `1W+1R`: active-1 pure-read throughput was effectively tied with `1W+2R`, while active-4 and active-10 pure-read and mixed throughput favored one reader; mixed samples recorded 2, 8, or 20 stream flushes and zero `SQLITE_BUSY`/`SQLITE_BUSY_SNAPSHOT`. The split reserves reader capacity because queued writers wait on the single writer pool rather than consuming reader connections; direct reader writes fail through `query_only`.
- File-backed regressions use multiple physical `*sql.Conn` handles and real repository entry points to verify pool settings, per-connection pragmas, WAL behavior, atomic writes, caller-context-bounded lock waits, timeout restoration, terminal stream-output protection, claims, Automation leases, thread inputs, attachment retirement/publication, incremental vacuum, serialized startup, and startup-failure cleanup. Coverage includes the server confirmation-secret failure after `RegisterDedicatedWriter`, proving both handles close and the registry is removed rather than testing only database bootstrap failures.
- The final topology selection uses duration-based measured phases long enough for the approximately 500 ms execution-output ticker to fire. The earlier short `-benchtime=100x` run with `stream-flushes=0` was superseded; accepted mixed samples recorded positive flush counts at active workloads `1/4/10`, and no zero-flush candidate was used for the `1W+1R` selection.
- All pooled write and write-with-`RETURNING` entry points must exercise deadline, cancellation-only, early-cancellation, successful restoration, and failure cleanup behavior. Task-goal update paths and attachment creation now use the bounded helper; held-writer regressions cover cancellation/deadline outcomes plus pooled `busy_timeout=5000` restoration. Transaction-owned executor variants remain caller-scoped.
- The previous repository/vacuum timeout-handling drift is resolved: both use `internal/database/sqlite_busy.go` for cancellation-aware timeout binding, restoration verification, idempotent cleanup, retry classification, bounded restore contexts, and physical-connection discard. Focused held-lock, restoration, and race regressions should continue to cover the shared boundary rather than reintroducing package-local copies.
- High-cardinality deletion paths retain indexed ownership lookups. Preserve query-plan assertions for indexed searches and production-shaped deletion/concurrency fixtures.
- Attachment tests cover Chat clearing, queued/immediate publication rollback, direct failures, shared-reference retention, durable session retirement, and both upload-first and retirement-first publication-fence orderings.
- Performance changes must preserve ordering, authorization, cancellation, retries, lifecycle behavior, persistence, and projection semantics. Use representative fixtures and record query/SQL/process/I/O counts, allocations, response sizes, and contention measurements.
- The 2026-08-28 #880 fix evidence confirms that a direct `GetDefinition` versus `Exists` benchmark is only existence-path evidence. The accepted end-to-end evidence uses the same migrated SQLite fixture with 10/50 nodes carrying 4 KiB configuration, one fake GitHub provider, and one tracked pull request: at 50 nodes, repeated direct existence samples measured `288,886–296,655 ns/op`, `382,786 B/op`, and `2,982 allocs/op` before versus `3,251–3,381 ns/op`, `632 B/op`, and `18 allocs/op` after. Repeated E2E samples reduced 10-node manual refresh plus Live rendering from `745,313–776,826` to `636,605–681,269 ns/op` and background refresh from `324,171–351,683` to `209,011–215,802 ns/op`; 50-node manual fell from `1,239,699–1,362,718` to `916,241–951,945 ns/op` and background from `502,768–508,382` to `201,183–218,942 ns/op`, with background allocations falling `3,300` to `330`. Gated single-connection tracing showed background graph loads `1 -> 0`, `WaitCount 2 -> 0`, and `WaitDuration 101.603–102.737 ms -> 0`; manual graph loads fell `2 -> 1`, while the necessary Live load and one provider call remained. Focused race tests, `go vet ./...`, `go build ./...`, `go build ./cmd/server`, the uncached `go test ./internal/... -count=1 -timeout 60s`, repeated benchmarks, contention tests, and `git diff --check` passed. The authorized PR reuse call confirmed live PR/source head `38deecc`; local implementation commit `edb8d68` has an identical tree and the live PR contains the same six issue-scoped paths. A fresh 2026-08-28 strictly read-only audit found the implementation narrow but did not clear the handoff: the authoritative PR body still reports only the 50-node direct benchmark, omitting concrete 10-node direct results and required end-to-end manual/background latency, waiter-latency, `WaitCount`, and `WaitDuration` evidence; the existing-PR reuse path ignored the supplied updated body, and no authorized body-edit capability is exposed, so unauthorized mutation is not an option. Live CI also has a failed non-experimental `Packaged update (macos-15-intel, amd64)` desktop packaged-update E2E check; the main suite and other packaging rows passed. Do not claim #880 complete until the publication evidence/CI blockers are resolved and a fresh strict audit passes.

Implemented bounded/projection paths:
- Templates, Pulse, worktree cleanup, Schedule calendar, Personality cards, Automation transition indexes, stale external-PR discovery, GitHub Dev Inbox discovery, Chat model selection, Agent model pickers, standalone Skills, Alerts, task-detail metrics, Reflection recent executions, channel target lookup, and task-turn skill-catalog filtering use compact projections where summaries are sufficient.
- Vision fallback in `resolveVisionRoutingDecision` has semantic SQL-projection, credential-eligibility, tier/default selection, selected-row hydration, and environment-fallback regressions. Its production-shaped benchmark uses at least 50 large model configurations plus a single-connection contention check; compact selection plus one full detail lookup enforces `<=200 µs/op` and `<300 KB/op` budgets.
- Runtime `list_models`, `get_model`, and `view_settings` use compact summaries. `view_usage_analytics` uses compact local-only account/usage data without credentials or dashboard-only aggregates.
- Worker model-capacity paths use compact model rows; project-capacity counts use category/status/project indexes; API Chat status polling uses compact execution status plus a batched non-Chat task lookup.
- Startup attachment reconciliation uses unordered path reads while preserving task/chat upload-root boundaries. Browser/channel `create_task` selection uses only fields needed for fallback, explicit selection, and `auto_start_tasks`.
- Chat queued-input recovery uses sparse indexed keyset paging. Browser Chat prompt context hydrates compact selection options after full execution model selection.
- Reflection scanning validates the complete JSON array before emitting filenames. Task-thread polling omits large prompt/chain/swarm blobs while detail/history retain full hydration.
- Task Detail metadata/metrics and status polling use compact projections; initial forms and deliberate history/detail routes retain full hydration. Regression coverage must ensure badge/status queries exclude large Agent/execution fields and preserve project, disabled, archived, missing, invalid-ID, and full-detail behavior.
- Multipart uploads use endpoint-aware caps and a raw limiter that handles split headers, invalid boundary-looking prefixes, delimiter whitespace, and valid multi-file totals. Completed/error transcript bubbles use static raw-content markup and one shared hydrator.
- GitHub publication batches tracked mode lookup, skips untracked symlinks, and preserves deterministic mode/order behavior.
- Incremental Makefile generation uses shared freshness checks for build, desktop, and run. Clean checkouts can seed stamps without generators; malformed state, source changes/additions/removals, missing outputs, and generator-version changes regenerate conservatively. Swagger freshness covers annotated API files, non-test model/viewmodel files, non-test `internal/update` files, and execution-repository schema. Generated-file checks and deliberate staged-deletion regressions remain required.

Open performance and correctness gaps:
- Bounded-projection or indexing gaps remain in Backlog, Insights, Architect, Automation work-item/history/portfolio, swarm-child, Chat-context, autonomous-trigger, Skill Analytics, plugin-state, agent-owned-skill, scoped-file, task-board, execution-analytics, PR-feedback, code-review, Automation Live, Email receipt, Models refresh, Channels settings, and Automation history paths (`#269`, `#294`, `#300`, `#314`, `#321`, `#327`, `#330`, `#345`, `#350`, `#355`, `#358`, `#457`, `#490`, `#504`, `#529`, `#541`, `#546`, `#555`, `#565`, `#572`, `#594`, `#623`, `#668`).
- Schedule calendar issue `#867` has a redundant SQL sort because results are immediately re-bucketed and sorted in Go; acceptance should compare query plans and production-shaped latency without conflating it with calendar projection work.
- Runtime `view_task_thread` issue `#887` tracks an unbounded execution-history read: the tool advertises `offset`/`limit`, but the current handler loads all chronological executions and slices them afterward. On a 200-execution fixture with 4 KiB prompts and 64 KiB outputs, the current path read 13.93 MB and allocated 14.30 MB at roughly 2.83 ms per operation, versus 1.39 MB, 1.42 MB, and roughly 0.291 ms for a count plus 20-row page; both plans used the existing task/time index. This is distinct from browser thread/history polling issues `#39`, `#541`, and `#826` and workflow-execution issue `#465`.
- Hosted-Ubuntu dependency-cache workflow `#228` has strict sample/comparator requirements and is not accepted until artifacts exist.

CI and validation setup:
- `OPENVIBELY_SKIP_BROWSER_PERF=1 go test ./... -count=1 -timeout 240s -coverpkg=./... -coverprofile=coverage.txt` is the primary Actions coverage/compile gate and includes `cmd/server`; do not add a redundant default server build without a distinct purpose.
- Preserve generated-file cleanliness checks and templ coverage exclusions. Packaged-update CI runs native update tests plus binary/desktop packaged E2E across Linux, macOS, and Windows rows; Windows ARM is experimental.
- Linux desktop dependency caches retain runner, architecture, and package-manifest identity, pin action refs to full SHAs, treat cache restores as untrusted on non-success, and publish machine-readable setup/job timing artifacts. Windows rollback E2E must stop restored helper processes before cleanup.

Validation conventions:
- Prefer `make test`, `make test-cover`, or `go test ./... -count=1 -timeout 120s`; raw 60-second full-suite runs can time out under load.
- Use readiness polling instead of fixed sleeps; guard timing-sensitive tests with `testing.Short()` where appropriate.
- Distinguish touched-scope regressions from environment failures such as desktop/config PATH, macOS Wails linker warnings, SQLite locks, date-sensitive schedules, and plugin-marketplace network timeouts. On macOS, `TMPDIR=/private/tmp` is the established fallback; repeatable Git exit `69` may require Xcode-license acceptance.
- Real-browser coverage is required for HTMX history/restoration, streaming offsets, transcript scrolling/hydration, drafts, pending attachments, stale responses, live refresh, drag/drop, keyboard shortcuts, and DOM timing. Desktop/Wails changes need native WebKit or packaged-desktop evidence; markup inspection and generic Chromium simulation are insufficient.
- Browser performance fixtures run over localhost HTTP, not `file://`, with explicit DOM pass/fail markers. Schedule layout tests use production-like `ScheduleContent` and app-shell geometry. Retry tests inject clock/backoff hooks rather than real sleeps.
- `NewTestContext` enables local repo paths by default; disabled-path tests call `SetLocalRepoPathEnabled(false)`. Chat selector tests use `chat-select-change` with `e.detail.value`. Malformed-JSON logs in expected service error paths are not failures. Concurrency tests assert final observable state rather than notification delivery timing.
- Composer browser coverage includes idle/active Enter, Meta/Ctrl+Enter, Meta/Ctrl-click Send/Stop, and iOS detection. Markdown-only conflict resolution normally skips build/test unless code or generated artifacts are touched.

Known coverage gaps:
- `TaskGoalService.ResumeGoalStoppedByUser()` lacks a dedicated regression test.
- Completed-task Detail edit/goal no-rerun tests should assert no queue/worker/lifecycle/schedule markers or extra execution/thread-input rows and preserved completion.
- `LiveEventsSSE` tests must verify request cancellation removes task/chat/file subscribers and max-subscriber failures return HTTP 503 while cleaning earlier subscriptions.
- The package-wide race run has a pre-existing order-sensitive fake Slack callback race; isolated and touched-scope race tests are the relevant evidence until that fixture is fixed.
