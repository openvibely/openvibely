OpenVibely has a large Go suite. Durable quality work emphasizes broad behavioral coverage and production-shaped performance evidence rather than narrow happy paths, raw logs, or task-by-task benchmark notes.

Coverage and fixtures:
- `internal/service` and `internal/handler` are the broadest seams, especially error, pagination, webhook, retry, scheduling, channel, and orchestration paths. `internal/service/llm_service.go` needs controlled caller mocks to avoid flaky tests.
- Generated `*_templ.go` is excluded from coverage summaries while template tests still run. Prefer behavior over granular tests around already-covered code; avoid blanket `t.Parallel()` with shared DB setup.
- `NewTestDB` uses isolated in-memory fixtures from an immutable serialized SQLite template with UTC, foreign keys, busy timeout, one connection, migrated schema, seed data, cleanup, and default-agent behavior.
- Runtime/action tests must cover ownership, authorization, pagination, mode restrictions, malformed JSON, provider-tool-incapable paths, and case-insensitive JSON-field presence. Explicit numeric zero must be tested as supplied invalid input, not mistaken for omission.
- Browser task-goal tests cover explicit/selected project ownership for get/set/pause/resume/clear, missing scope, unknown tasks, and foreign tasks without reads, leakage, or mutation. Alert tests cover compact list/detail hydration, shared Markdown/link sanitization, exact LF/CRLF/bare-CR copy, empty bodies, and light-mode contrast.
- Production-shaped integration tests must invoke the real service/repository and shared SSE/router boundary. Synthetic mutations or manually dispatched events do not prove claims, broadcaster transport, listeners, project isolation, or authoritative refresh.
- Changes/worktree coverage must prove recoverable failure refreshes retry actions, duplicate action suppression, genuine conflict guidance, project ownership, live eligibility, repository lease races, unusual filenames, squash/no-`MERGE_HEAD` recovery, and authoritative state. Kanban coverage must include selection/focus across refresh, grouped drops, navigation/history cleanup, stale card options, PR ownership failures, and browser geometry.
- Real Chromium/CDP interaction is required for pointer/hover/cascade, keyboard, focus restoration, dialog/menu, scroll, and HTMX replacement behavior. A source/template assertion alone does not establish browser behavior. Lifecycle viewport, Automation Live reconnect/run-now, task status icon, card pagination, and theme contrast have production-shaped browser coverage.
- Collection-selection browser coverage exercises real empty and mixed collection markup. The Channels empty fragment is rendered through `pages.SettingsContent` and checked in Chromium to ensure the searchable empty state gets no selection gutter or padding and the master control remains disabled, while mixed collection behavior remains covered. Production-shaped selection coverage also verifies second-click Filters dismissal, persistent master/search controls during selection, master uncheck restoration of Filters/Sort, configured provider-card selection, and Alerts’ selected Mark-as-read action. Channels bulk-removal handler/repository regressions prove one atomic request preflights mixed provider/webhook selections, rejects foreign or unsupported IDs without mutation, and rolls back settings and webhook state after a mid-transaction failure.
- Production Chromium now covers the shared card-list refresh regression: a successful bulk mutation manually replaces the collection root, then the replacement master checkbox selects and clears an eligible card and the replacement Filters control responds. This specifically protects the non-HTMX `outerHTML` path, which does not emit `htmx:afterSettle`, across the shared collection-card implementations.

Performance and SQLite evidence:
- Representative file-backed tests use multiple physical `*sql.Conn` handles and real repository entry points to verify the production `1W + 1R` layout, per-connection pragmas, WAL pressure, atomic writes, busy behavior, context-bounded lock waits, timeout restoration, terminal stream protection, claims, Automation leases, thread inputs, attachment retirement/publication, incremental vacuum, startup serialization, and failure cleanup.
- Timing phases must outlast the approximately 500 ms output ticker; a zero-flush short run is not topology evidence. Every pooled writer/`RETURNING` path needs deadline, cancellation-only, early-cancellation, timeout-restoration, and failure-cleanup cases.
- Preserve high-cardinality ownership/deletion indexes. Projection claims need direct and end-to-end evidence at representative small and large sizes, including manual/background paths, latency, allocations, query/wait counts, response bytes, and contention. A narrow microbenchmark is insufficient.
- Email receipt-first benchmarks cover mixed receipt states/sizes, full-body bytes, MIME work, fetch/command/receipt/`STORE` counts, allocations, elapsed time, grouped acknowledgement, and retry recovery; mailbox self-filter query reuse is tracked in `integrations_and_channels.md` (`#983`) while direct-call freshness/reload behavior remains covered.
- Endpoint-aware multipart tests cover per-file and request caps before side effects, split-header handling, invalid boundary-looking prefixes, delimiter whitespace, and valid multi-file totals. Transcript tests protect bounded history, static raw-content markup, and one shared hydrator.

Established compact-projection patterns:
- Templates, Pulse, worktree cleanup, Schedule calendar and primary-Agent picker, Personality/Channel/Alert cards, Automation transitions, stale external-PR and GitHub Dev Inbox discovery, Chat model selection, Agent model pickers, Skills, task-detail metrics, Reflection recent executions, channel target lookup, and task-turn skill catalogs use compact projections where summaries suffice.
- Vision routing uses semantic SQL projection and selected-row hydration; already-capable/no-image paths remain query-free. Runtime model/settings views omit secrets; usage analytics is local-only and compact. Worker model capacity, project counts, API Chat polling, and queued recovery use compact/indexed paths.
- `view_task_thread` uses payload-free count and bounded chronological execution pages; omitted/zero limits stop at the existing 80 KiB transcript budget. Query-plan tests protect `idx_executions_task_started_at` without temp sorting.
- Makefile/build freshness checks regenerate conservatively for malformed state, source changes/additions/removals, missing outputs, and generator-version changes. Swagger freshness includes annotated API files, non-test models/viewmodels, non-test update code, and execution-repository schema.
- Compact projections require exact runtime-path query coverage at representative sizes, including manual/background paths, latency, allocations, query/wait counts, response bytes, and contention. Canonical examples include scheduler admission, the Schedule primary-Agent picker, and the Agent `agent_list`; their behavior and ownership remain in the architecture/lifecycle topics.

Validation conventions:
- Prefer `make test`, `make test-cover`, or `go test ./... -count=1 -timeout 120s`; short uncached suites may time out under load. Use readiness polling rather than fixed sleeps and `testing.Short()` for timing-sensitive cases.
- The primary Actions coverage/compile gate is `OPENVIBELY_SKIP_BROWSER_PERF=1 go test ./... -count=1 -timeout 240s -coverpkg=./... -coverprofile=coverage.txt`, including `cmd/server`. Codecov acceptance uses hosted `line_coverage` for the exact commit; do not add redundant default builds without a distinct purpose.
- Preserve generated-file cleanliness, templ coverage exclusions, packaged-update native/E2E matrices, Linux cache identity/action pins, untrusted-cache handling, setup timing artifacts, and Windows rollback-helper cleanup.
- Distinguish touched-scope defects from environment failures such as desktop/PATH setup, macOS Wails linker warnings, SQLite locks, date-sensitive schedules, plugin network timeouts, Xcode-license Git exit `69`, and macOS temp-directory issues; `TMPDIR=/private/tmp` is the established fallback.
- Strict read-only audits perform no validation commands; skipped checks and hosted status must be stated separately from local results. Live publication evidence, not local benchmark output, determines whether a PR is complete.
