OpenVibely has a large Go suite. Durable quality work emphasizes broad behavioral coverage and production-shaped performance evidence rather than narrow happy paths, raw logs, or task-by-task benchmark notes.

Coverage and fixtures:
- `internal/service` and `internal/handler` are the broadest seams, especially error, pagination, webhook, retry, scheduling, channel, and orchestration paths. `internal/service/llm_service.go` needs controlled caller mocks to avoid flaky tests.
- Generated `*_templ.go` is excluded from coverage summaries while template tests still run. Prefer behavior over granular tests around already-covered code; avoid blanket `t.Parallel()` with shared DB setup.
- `NewTestDB` uses isolated in-memory fixtures from an immutable serialized SQLite template with UTC, foreign keys, busy timeout, one connection, migrated schema, seed data, cleanup, and default-agent behavior.
- Runtime/action tests must cover ownership, authorization, pagination, mode restrictions, malformed JSON, provider-tool-incapable paths, and case-insensitive JSON-field presence. Explicit numeric zero must be tested as supplied invalid input, not mistaken for omission.
- Production-shaped integration tests must invoke the real service/repository and shared SSE/router boundary. Synthetic mutations or manually dispatched events do not prove claims, broadcaster transport, listeners, project isolation, or authoritative refresh. Live-SSE transport coverage includes 50 scoped clients distributed across at least 10 projects and task IDs, asserts matching target events are offered and serialized only to their scoped clients, and preserves intentionally unfiltered global-stream delivery.
- Changes/worktree coverage must prove recoverable failure refreshes, genuine conflict guidance, ownership, live eligibility, repository-lease races, unusual filenames, squash recovery, stale Git refs, and no target mutation on failed fast-forward.
- Real Chromium/CDP interaction is required for pointer/hover, keyboard, focus, dialog/menu, scroll, geometry, and HTMX replacement behavior. Source/template assertions and page-side synthetic events are supplemental, not substitutes for native browser input.
- Collection-card tests cover empty and mixed markup, selection/filter controls after manual root replacement, and atomic Channels bulk removal without partial mutation. Task-board tests cover grouped drops, selection/focus refresh, stale options, portaled menus, complete batch ownership preflight, and Active-lane atomicity. Repository and handler regressions force a later selected-row failure or pre-drag state mismatch and require rollback before worker submission; they cover no-op existing-running cards and grouped lifecycle-owned rejection before side effects. A single lifecycle-owned card must instead preserve its authoritative queued-task-thread promotion, failed-follow-up retry, or swarm-planner route with its actual resulting lane/status, returning a controlled conflict for the rejected Running placement. Deterministic concurrent-transition tests pause after lifecycle-owned classification, commit a terminal/category/ownership transition, then prove the guarded queued-input, failed-retry, and swarm-owner handoffs create no execution or planner work and preserve the newer state. Running-lane coverage includes atomic durable-reservation creation, constrained-capacity/startup reconstruction, later task-thread FIFO ownership, stale cleanup, same-category terminal fencing, transient same-process reoffer after an injected reserved-claim failure, and end-to-end prompt/model edits that verify the original reserved execution records authoritative dispatch metadata. Production-rendered Chromium coverage drives a native grouped running-lane drop through the real handler/repository, verifies submitted visual order, state tokens, authoritative reconciliation, and fresh-reload persistence.

Performance and SQLite evidence:
- Representative file-backed tests use multiple physical `*sql.Conn` handles and real repository entry points to verify the production `1W + 1R` topology, connection pragmas, WAL pressure, atomic writes, busy behavior, bounded lock waits, timeout restoration, terminal stream protection, claims, leases, attachments, vacuum, startup serialization, and failure cleanup.
- Timing phases must outlast the approximately 500 ms output ticker; a zero-flush short run is not topology evidence. Every pooled writer/`RETURNING` path needs deadline, cancellation-only, early-cancellation, timeout-restoration, and failure-cleanup cases.
- Preserve high-cardinality ownership/deletion indexes. Projection claims need direct and end-to-end evidence at representative small and large sizes, including latency, allocations, query/wait counts, response bytes, and contention; a narrow microbenchmark is insufficient.
- A paginated SQLite name order using `COLLATE NOCASE` requires a matching `NOCASE` index definition for its filter and tie-break columns. Query-plan coverage must exercise the actual paginated query in both sort directions and reject a temporary order B-tree.
- Email receipt-first tests cover mixed receipt states/sizes, MIME work, fetch/command/receipt/`STORE` counts, allocations, grouped acknowledgement, and retry recovery. Mailbox self-address filtering must use one normalized poll snapshot while direct calls reload current settings; contention comparisons must use the same real SQLite hold for baseline and candidate.
- Task-thread performance tests must exercise the real asynchronous scanner with multi-megabyte, high-line-count output and native Chromium input. Workers may outlive the former three-second cutoff but remain bounded by the owning render deadline; worker failure must render escaped plaintext rather than synchronously rescanning on the UI thread. The broader deferred-output design still needs bounded initial projection, authorized exact-output loading, indistinguishable ownership `404`s, loaded-state preservation, and production-shaped end-to-end evidence.
- Endpoint-aware multipart tests cover per-file and request caps before side effects, split headers, boundary edge cases, and valid multi-file totals. Transcript tests protect bounded history, static raw-content markup, and one shared hydrator.

Established projection patterns:
- Use compact projections for list, polling, routing, analytics, selection, and discovery surfaces; hydrate rich records only after selecting a specific item. Preserve secret exclusion, scope filters, stable ordering, pagination, and query-free paths when no references are present.
- `view_task_thread` uses payload-free counts and bounded chronological execution pages; omitted/zero limits retain the 80 KiB transcript budget. Query-plan tests protect `idx_executions_task_started_at` without temporary sorting.
- Task-thread follow-up context, including direct review submission, selects the newest 21 execution rows with `ListByTaskChronologicalLimit` before filtering and chronological restoration. Production-shaped file-backed evidence must compare this bounded path against all-history loading for payload rows/bytes, wall time, allocations, concurrent-reader contention, and the index-backed no-temporary-sort plan; rich execution-history/detail routes remain unbounded when their users request historic output.
- Automation save resolves Agent references with one bounded compact selectable-reference projection per candidate; no-reference saves remain query-free. Test shared/distinct references, scope/filter boundaries, rollback, builder/Chat paths, rich-field exclusion, and representative cardinalities.
- Makefile/build freshness checks regenerate conservatively for malformed state, source additions/removals/changes, missing outputs, generator-version changes, Swagger inputs, and relevant model/schema changes.
- Direct model-usage attribution follows the compact-projection pattern: authoritative project context is query-free, while work-directory fallback scans only unordered `id`/`repo_path` rows through a covering `(repo_path, id)` index. Regression evidence protects zero explicit-context lookups, absence of temporary ordering, provider-success/failure behavior, nested/worktree/Windows path semantics, and production-shaped 1/50/500-project latency and allocation targets.
- Task Detail terminal-action refreshes use a dedicated read-only `id`/`status` metadata projection rather than a partial mutable `models.Task`; preserve the existing full-record `GetByID` path for rich detail, editing, task-thread, dispatch, and mutation flows. Regression coverage must protect button states and missing-task behavior, the two-column SQL projection, primary-key lookup plan, and representative file-backed read/contention characteristics.

Validation conventions:
- Prefer `make test`, `make test-cover`, or targeted `go test` runs with `-count=1 -timeout 120s`; use readiness polling instead of fixed sleeps and `testing.Short()` for timing-sensitive cases. Full-repository validation must use the CI-style `-timeout 240s`: `internal/handler` can exceed 120 seconds under combined package load while passing in isolation and at the larger timeout, which is a runtime-budget constraint rather than an assertion failure.
- Default to ordinary tests. Use `go test -race` only for a concrete race-sensitive invariant changed in production (or an explicit user/issue/CI requirement), and keep that run to the smallest deterministic functional regression; concurrent-load evidence alone does not justify it, and performance or allocation gates must not run under the detector.
- The primary Actions coverage/compile gate is `OPENVIBELY_SKIP_BROWSER_PERF=1 go test ./... -count=1 -timeout 240s -coverpkg=./... -coverprofile=coverage.txt`, including `cmd/server`. Codecov acceptance uses hosted `line_coverage` for the exact commit.
- Preserve generated-file cleanliness, templ coverage exclusions, packaged-update native/E2E matrices, Linux cache identity/action pins, untrusted-cache handling, setup timing artifacts, and Windows rollback-helper cleanup.
- Distinguish touched-scope defects from environment or known baseline failures. Report the narrow passing scope and exact broad failure; exact-head hosted checks and live publication evidence cannot be replaced by local success.
- Strict read-only audits run no build, test, generation, formatting, or other write-capable validation commands and must disclose skipped checks.

Current gaps:
- Projection/indexing work remains across Backlog, Insights, Automation history/live, swarms, Chat context, skills/plugins, task boards, review, Email receipts, Models, and Channels. Keep ownership in the most specific topic rather than accumulating task-by-task benchmark history here.
- Tracked performance gaps include Schedule calendar sorting (`#867`), unnecessary Air templ generation (`#903`), scoped-file no-match grep materialization (`#936`), repeated swarm child/parent/list reads during terminal-completion reconciliation (`#975`), duplicate Automation Live graph loading (`#985`), repeated startup Memory Curator reconciliation (`#1007`), per-schedule Automation ownership lookup fan-out during due-schedule dispatch (`#1018`), repeated full remote GitHub issue-history scans before local discovery pagination (`#1028`), unbounded `view_pulse` agenda rows inflating model context (`#1036`), rich project-row materialization on the three-second Workers capacity polling refresh (`#1080`), and unnecessary full project-row hydration by the web/API `switch_project` runtime action (`#1087`).
- The Task UI must continue using compact scalar Agent rows for board badges and create/edit/detail selectors, rather than rich configuration hydration. Preserve production-shaped file-backed SQLite coverage at high Agent cardinality, including response size, allocations, query count, and concurrent-read behavior.
- Timing-sensitive tests can fail under combined package load while passing in isolation; reproduce in isolation before classifying a product regression, but never use that as clearance for an unresolved exact-head hosted check.
