OpenVibely uses server-rendered HTMX/templ UI with shared SSE live updates. Durable UI rule: SSE announces that something changed; HTMX/server-rendered templ fragments remain authoritative state.

Realtime and diff contracts:
- Shared `/events/live` multiplexes task, Chat, mixture-progress, and file-change invalidations. Sidebar JavaScript dispatches `sse-task-event`, `sse-chat-live-event`, `sse-file-change-event`, and `sse-live-connected`. Intentional global consumers may omit scopes, but ordinary sidebar streams carry the selected `project_id`, retarget their connection when project/navigation scope changes, and add `task_id` on Task Detail where file-change invalidations require it.
- Chat interactive-question requests use the same project-scoped live SSE path as other Chat events. `chat_user_input_requested` carries the generated request ID, execution ID, and typed questions/options; the browser renders a fixed accessible card with DOM text/attributes rather than model HTML, requires a complete selection, submits once, disables controls, and keeps selected labels visible. Requests are live/in-memory only, so a refresh or restart cannot recreate stale actionable controls. If the provider is still waiting, a page reload or SSE reconnect can therefore strand the run because the request is emitted once and the rebuilt Chat has no replay source; open bug `#1104` tracks the missing recovery behavior.
- Live-event subscriptions route at the typed broadcaster boundary before fan-out: each task, Chat, and file-change broadcaster maintains deliberate global subscribers plus project/task-keyed subscribers, and publishes only to the relevant keyed buckets plus globals. The shared core now uses immutable copy-on-write snapshots rebuilt only for affected buckets when membership changes; stable publishes iterate the global and matching snapshots directly without combining them or allocating a temporary subscriber slice. Publication holds the broadcaster read lock through bounded nonblocking sends while unsubscribe takes the write lock and closes only afterward, preserving configured capacities, slow-subscriber drops, disconnect cleanup, and concurrent publish/unsubscribe safety. Issue `#1155` is implemented in PR `#1164`; any future optimization must preserve routing and subscription-churn semantics.
- Typed broadcaster routing and sidebar scope retargeting must carry authoritative project IDs, including mixture-progress events from normalized requests. Project-keyed subscribers receive only matching project/task events, while deliberate global subscribers retain delivery.
- Committed Automation claims/failures publish project/task-scoped `task_board_updated`; Tasks performs a scoped/debounced authoritative refresh. Automation Live performs an identity-scoped refresh on `sse-live-connected` because invalidations may be missed while disconnected.
- `window._tabVisibility` owns broad realtime visibility and pauses polling while hidden. Per-execution `/events/chat/:exec_id` is the token stream; SQLite is the durable reconnect source and `events.ExecutionStreamHub` carries hot deltas by exact execution ID, with bounded subscribers, nonblocking slow-consumer drops, and terminal close.
- `internal/events` has one broadcaster core for task, chat, and file-change events. It owns locking, capacity, cleanup, nonblocking publication, and counts; typed wrappers keep public APIs/capacities. Cancellation removes subscribers; capacity failures clean earlier subscriptions and return `503`.
- `llmstream.Writer.Write` publishes cumulative raw UTF-8 byte offsets after unlocking. Seeded/`WriteText` content is not republished and token writes do not synchronously flush SQLite. Periodic/final persistence prevents an older periodic snapshot overwriting a newer terminal flush.
- Execution SSE subscribes before database catch-up, clamps untrusted UTF-8 offsets, skips duplicate/partial overlaps, and performs targeted durable catch-up when deltas drop. Terminal events follow durable terminal writes; completed/cancelled map to `done`, failures to `error`, and missing output is replayed before terminal status.
- File changes are invalidation/snapshot signals. `diff_snapshot` is metadata-only; full diffs remain in database/routes and browsers refresh authoritative Changes fragments. Changes is lazy unless `tab=changes`, and direct and lazy routes must agree. Recoverable merge failures return refreshed fragments with feedback and retry actions; genuine conflicts expose recovery guidance plus Resolve/Abort and hide ordinary merge actions. Kanban task-card Fast-forward operation failures/conflicts likewise return a `200` swap-safe authoritative board refresh with an `openvibelyToast` failure event, while stale eligibility/precondition failures retain controlled non-success responses. Worktree lease/eligibility rules are canonical in `worktree_and_lineage.md`.
- Diff viewers use GitHub-style load envelopes, oversized placeholders, deletion summaries, constrained rename/copy headers, and viewport-safe overflow. `app_settings.ui.diff_view` is `inline` by default, accepts `split`, and normalizes legacy `unified`; only user toggles persist it.

Chat, task-thread, and lifecycle rendering:
- Chat and task-thread streaming batch DOM updates and force a final flush. Chat reconciles its `streaming-message-<exec_id>` node; task-thread appends authoritative execution fragments. Start/input-applied events must not replace a fresh stream with a page reload.
- Terminal reconciliation uses persisted status/output regardless of event arrival order, replaces loading dots, and reconciles composer state. Queued/steering inputs remain compact composer rows, with attachment indicators preserved through refresh/reconnect/live creation. Promoted runs remove pending rows and attach their stream.
- Completed/error bubbles use compact `data-raw-content` and one shared scanner/queue per page or fragment for Markdown/code hydration, sanitization, links, copy, partial failed/cancelled output, pagination, morph swaps, and `hx-preserve`. Tool results retain full fidelity in bounded responsive containers. Browser Task Detail eagerly loads Thread after roughly 100 ms and pages five executions by default; unlike model-facing `view_task_thread`, this path has no byte budget, so multi-megabyte executions can block usability. The durable scanner fix keeps large code-range work asynchronous past the former three-second cutoff, bounded by the owning render deadline; genuine worker failure renders escaped plaintext instead of synchronously rescanning. Matching rendered revisions are skipped only when visible content remains, so blank containers rehydrate. A bounded initial-output projection plus authorized exact-output loading remains proposed rather than implemented.
- The global Chat and Task Detail Thread render one shared accessible `Latest message` button above their transcript scrollports. Its controller delegates the actual return-to-bottom transition to the keyed `ChatScrollTracker`, so streaming, SSE/HTMX replacement, lazy earlier-message pagination, layout/attachment resizing, and history restoration preserve the same reader intent. Activation immediately jumps to the latest message while restoring pinned intent. Scroll, `ResizeObserver`, and `MutationObserver` bindings are lifecycle-safe and are reinstalled or destroyed when the scrollport changes; real Chromium coverage exercises both surfaces, appended updates while scrolled up, immediate return-to-latest, Thread replacement, and history restoration. The button's centering is owned by a full-width pointer-inert wrapper; the interactive button itself must remain transform-free and pointer-enabled because DaisyUI pressed-state transforms can otherwise move its hit target and require repeated clicks.
- Alert inspection lazily reuses the same Markdown/sanitization/code-copy/link pipeline. Exact body bytes are separately Base64-encoded UTF-8 for clipboard decoding immediately before copy, preserving LF, CRLF, and bare CR despite `<pre>` normalization; fallback is escaped inert text.
- Lifecycle activity is project-scoped and prompt-safe, ordered by `(started_at DESC, id DESC)`, and paged with keyset cursors. Refresh/reconnect renders a bounded newest page; retained nonterminal rows can be rehydrated individually, missed older history appears as chronological gap sentinels, and continuations load bounded pages without draining history. Cleanup cancels timers/listeners/requests and invalidates detached callbacks without losing anchors.
- Task-run validation evidence remains a review gap: execution/task-detail data has status but no explicit per-run validation field/projection (`#927`). Lifecycle activity stays separate from the main Thread.

Shared composer and navigation:
- The shared composer contract (markup, send/queue/steer semantics, authoritative OOB state, primary-action states, accepted-submit clearing, and lost-`409` retry) is canonical in `chat_thread_system.md`. This topic owns cross-page autofocus, navigation, and DOM-lifecycle behavior.
- Composer autofocus is owned by the same `ChatInputForm` contract, rather than by Chat or Task Detail page-specific systems. It requests after full-document, HTMX-fragment, lazy Thread, and history-restoration lifecycles, then resolves the connected visible textarea at cancelable task-queue settlement and focuses with `preventScroll`. Requests are idempotent and decline when another meaningful visible control, open dialog/menu, unsaved-change confirmation, or intentional history-focus restoration owns interaction. A real sidebar return is the narrow exception: the manager records a focused `[data-nav-base]` link only for the matching `#main-content` HTMX swap, consumes it once to allow the newly rendered composer to take focus, and clears it on user interaction, so ordinary later swaps cannot steal focus. Closed ARIA dialogs and controls inside closed native dialogs are not active blockers. Task Detail signals the shared request only after lazy Thread content is live. History-restoration deferral is manager-owned: its timer is cleared by shared cancellation and checks captured cancellation/interaction epochs before requesting focus. Composer or main-content swaps cancel it, but unrelated sidebar swaps must not suppress valid restored-composer focus. Production-shaped browser validation for these focus and navigation behaviors belongs in `testing_coverage_and_performance.md`.
- Desktop Chat actions use a semantic button with `aria-expanded` and `data-chat-actions-open`, not a focusable DaisyUI label. Outside activity, focus-out, history restoration, and fragment initialization close it; Escape restores focus. Clear Chat retains exact destructive confirmation. Overlapping action-only refresh stale-response handling remains `#48`.
- Server-rendered `PageTitle` markers own browser titles. Programmatic navigation uses `window.openVibelyNavigate`; history misses request full documents while ordinary HTMX requests remain fragments. Revision no-ops cancel before capturing draft/scroll, cleaning EventSource, or mutating DOM. Final transcript parsing treats LF/CRLF/bare CR equivalently without changing source bytes, escapes raw `<` outside protected code, sanitizes HTML/URLs, and keeps malformed/example controls inert.
- Deep breadcrumb selectors are compact, project-scoped search results. Task, schedule-origin Task, and Automation searches include the currently selected item when its name/title matches the query and preserve its selected marker; the current item is omitted only when it does not match. Clearing the query restores normal current-item visibility and current-first ordering. A Task selector opened with the allowlisted `from=schedule` origin must require live Schedule-calendar membership through an existing schedule row for that task, excluding ordinary unscheduled and foreign-project tasks; a retained `category = 'scheduled'` value alone is stale evidence after a schedule is deleted. Disabled schedule rows remain eligible. Normal Task selectors remain broader. The selector carries the origin separately from the active tab and selected Task destinations preserve both `from=schedule` and the allowlisted tab. For empty Task and schedule-origin searches, the backend fetches the eligible current task separately and serves the remaining page in `updated_at DESC, id ASC` discovery-index order, avoiding a temporary sort; typed relevance searches retain their current-first exact/prefix/contains ordering. Backend and browser regression coverage belongs in `testing_coverage_and_performance.md`.
- Review navigation still lacks visible Thread/Reflection links to execution details (`#365`, `#380`), and hard refresh after cancellation lacks the same explicit terminal marker as completed/failed threads (`#226`).

Cards, pagination, and responsive behavior:
- Card lists use `data-card-search` and `window.refreshCardSearches`. URL search seeds only initial render. Refreshes carry bounded `card_window`, preserve search/window/anchor/focus, and continue from explicit rendered offset. Models sort navigation must request the current loaded window through `cardPaginationRefreshURL` with `card_window=1` while keeping `card_window`, `page_size`, `page`, and `offset` out of the browser-history URL. Fixed injected cards can participate in replacement focus/anchor snapshots without affecting page counts, offsets, appends, or deduplication. Pagination completion is silent: hide sentinel/status when `hasMore=false` and retain transient loading/error/retry hooks without an end marker.
- Automation portfolio cards are keyboard-accessible: each eligible saved card has a meaningful accessible name and visible focus treatment, card navigation remains project-scoped, nested action controls do not trigger card navigation, and Enter/Space activation ignores repeated keydown events so a held key cannot issue duplicate navigation requests. Production-rendered Chromium coverage exercises native mouse input, Tab traversal, Enter/Space activation including repeat protection, search, pagination, and active/paused cards.
- Shared collection-card toolbars use a checkbox master control for currently loaded eligible cards rather than a text `Select loaded` action. The master reflects checked/indeterminate state, query changes clear selection, and fixed ineligible cards receive disabled checkboxes with accessible explanations while eligible dynamic cards remain selectable. Selection mode keeps the master checkbox and search mounted, replacing only Filters/Sort with contextual actions; unchecking the master clears selection and restores those query controls. Filter popovers use explicit `aria-expanded` and class-driven state, so a second trigger click, outside click, or Escape dismisses them; injected selection gutters are title-aligned and reinitialized after HTMX swaps. On desktop, toolbar-owned card roots reserve the 32 px selection gutter in initial CSS before paint, excluding empty-state cards; the installer injects and aligns the checkbox without adding post-paint card padding, preventing title movement on initial load and server-backed search replacement.
- Shared card-root refreshes through `refreshCollection()` reinitialize the replacement toolbar after manual root replacement, preserving master-checkbox, filter, and bulk-action behavior for Alerts and other collection-card pages.
- HTMX/root replacement aborts requests, clears timers/observers/listeners, and snapshots/restores search, viewport, anchor, and focus. Sort transitions use an explicit absolute-viewport restore mode so a reordered anchor cannot pull the viewport to its new rank; toolbar-control focus is restored after native-select detachment while card/action fallback focus remains synchronous. Focus restoration rejects hidden/inert/disabled/aria-disabled targets, avoids reopening menus, and falls back to a visible adjacent card or search input. Shared collection sort controls use the responsive `card-sort-control` sizing contract rather than page-specific widths. Automations, Models, and Personalities default to `Name A-Z`; Models excludes ambiguous `Default` and plain `Name` options, while Personalities excludes `Curated` only as a sort choice and retains its curated metadata/filtering. All repository-backed card `name_asc`/`name_desc` orders are case-insensitive with deterministic original-name and ID tie-breakers, rather than SQLite binary/ASCII case grouping. Automation `updated_desc` (`Recently updated`) orders persisted `updated_at` newest-first with `id ASC` as a stable tie-breaker, before repository pagination and in handler-rendered card pages. Channels exposes `Name A-Z` and `Name Z-A` for the complete visible collection, including configured providers, the Outbound Target card, and webhooks. Webhook pagination remains scoped by `data-webhook-id`, and full/replacement responses render the mixed collection in authoritative order before JavaScript; later appends use the same folded-name, original-name, and stable-identity comparator. Backend collation/index and non-ASCII ordering requirements are canonical in `integrations_and_channels.md`. Configured provider cards are selectable; Outbound Target cards are not. Bulk removal refreshes authoritative state only after the atomic server request succeeds.
- Channels preserves `data-search-card` on its empty-state placeholder while shared selection excludes empty states from checkbox/control injection, so empty cards receive no selection padding.
- Sidebar collapse and Ctrl/Cmd+B use one helper for DOM/accessibility state, localStorage mirror, and background `/ui/preferences` persistence. Full documents embed early state; fragments do not fetch preferences. Sidebar selection is hover-only, not DaisyUI `.active`.
- The shared project switcher keeps `#project-selector` as the compact identity-only select with its established collapsed `select select-bordered select-sm w-full sidebar-project-select` visual styling and existing change/persistence path, while exposing an accessible searchable dialog. The collapsed trigger retains the built-in DaisyUI select arrow; do not replace it with a custom caret SVG or `bg-none`. Project and Task/Automation breadcrumb selectors use one neutral `SearchableSelector` templ component and one shared browser controller for the dialog shell, direct-child panel, search/results controls, opening, closing, positioning, filtering/search events, clearing, keyboard traversal, result selection, and HTMX/history lifecycle handling. Shared selector popups have no header or close button: the inset search box is first, followed directly by available results. Give the dialog a direct accessible label such as `Select Task`; Escape and backdrop clicks remain the supported dismissal paths. Do not reintroduce project- or breadcrumb-specific copies of that shell or controller. Data-specific behavior remains configurable: project options filter locally and dispatch the existing hidden-select change event, while breadcrumb results load through HTMX and navigate by URL. Local project search includes the currently selected project when its name matches and preserves its check/`aria-selected` marker; it hides the current project only when the query does not match, and clearing the query restores every project and normal current markers/order. Local project filtering uses only the inline direct `input` and native `search` hooks exposed by the shared component; do not add delegated local filtering listeners, because that duplicates synchronous option scans and positioning for every event. Local filtering must set the option `hidden` property and toggle the Tailwind `hidden` utility class because each option also has `display:flex`, which can otherwise leave a nonmatch painted. Both modes use plain `type="text"` search inputs so browsers do not render a native X, and neither mode adds a custom clear control; users clear queries through ordinary text editing, whose `input` event restores unfiltered results. Their option rows intentionally match Automation-card kebab items with compact `px-4 py-2` geometry and `bg-base-content/10` hover highlighting; do not restore selector-specific `min-h-11`, narrower `px-3`, or `hover:bg-base-200`. Their search controls likewise match the Automations collection search: an inset `p-2` area containing the rounded, bordered `card border border-base-300 bg-base-100 shadow-sm` shell and its borderless `px-4 py-2` input, so the search border never touches the popup border. Shared class constants remain in `web/templates/searchable_selector_styles.go`; the reusable shell/controller lives in `web/templates/searchable_selector.templ`. The project dialog must not add a project-only DaisyUI `.modal-box` wrapper or `.ov-modal-close` styling layer. Project options use the breadcrumb check-column treatment and `role="option"` plus `aria-selected`, not a project-only `Current` badge or `aria-current` (reserved by sidebar navigation tests). The dialog uses fixed viewport positioning attached to the trigger, with the trigger's left edge as the preferred project-popup anchor; horizontal clamping, upward fallback, and scroll/resize repositioning handle constrained viewports. The shared controller resolves live nodes on every event so full-page, HTMX, and direct DOM replacements cannot leave stale cached controls. The shared controller owns document/window listeners through a stored `AbortController`; reinstalling it tears down older listeners to prevent duplicated filtering and positioning. Selection preserves unsaved-change confirmation, same-page-family routing with `project_id`, `window.openVibelyNavigate`, default-first ordering, and empty-workspace fallback. The panel inherits the dialog's dynamic maximum height and remains overflow-hidden, leaving the results pane as the sole vertical scroll owner.
- Clipboard uses `window.openVibelyCopyText`; toasts use `openvibelyToast`, account for native-dialog top layers/mobile insets, and deduplicate Automation-start notices by neutral `toast_key`. Worktree success paths preserve unrelated HTMX trigger keys.
- Destructive deletes use one accessible DaisyUI `<dialog>` pattern. Task-board Delete All is page-scoped with allowlisted category/project inputs, duplicate-submit protection, retry, and authoritative refresh. Project deletion keeps its confirmation open and its confirm action disabled while the request is in flight, displays an inline retryable error when the relational deletion fails, and closes/navigates only after authoritative success. A committed filesystem/runtime cleanup warning is carried through both HTMX and ordinary redirects as the fixed `project_cleanup_warning=1` marker; the destination page consumes it, removes it with `history.replaceState`, and renders the sticky `project-cleanup-warning` toast. Cancel/Escape restore the invoker or visible kebab; confirmed deletion deliberately suppresses invoker restoration so a closing dialog cannot reopen a menu.
- Chat/thread panes, cards, badges, composers, and tool output use `min-w-0` and bounded inner overflow without clipping roots/shadows/tails. Mobile controls truncate selectors while action clusters remain intact. Task Detail tabs are Prompt, Goal, Git Worktree, followed by the remaining tabs in a horizontally scrollable row.
- Task state icons are server-rendered from authoritative projections and remain accessible/shrink-safe. `GoalMet` is derived only for completed tasks with an achieved persisted goal; merged status has precedence and goal never masks running, failed, cancelled, blocked, or other non-completed states. The board derives it with SQL `EXISTS`; the documented SVG in `docs/task-status-icon-options.html` is canonical. Failed/cancelled rows are excluded from active dropzones.
- Task Details Changes surfaces stay contained at 320px. The Lifecycle card uses a full-height flex/min-height chain and an activity-owned scrollport; explanatory text must not be a direct `.card-body > p` flex-growing child. Completed Threads show Changes, warranted merge guidance, or no-diff/no-output guidance. The board uses one/two/three columns across phone/tablet/desktop and places `+ Add Task` beside the title.
- Schedule calendar cards currently expose schedule identity and enabled state for navigation but do not offer local Pause/Resume controls; suggestion `#1146` tracks adding those controls while reusing `ScheduleActionService.Toggle`, preserving Task Details behavior, project ownership, drag interactions, and already-fired one-time error semantics. They also lack a local `Run Now` action for an occurrence; suggestion `#1151` tracks exposing the existing task execution path without changing cadence, while preserving card navigation, drag-and-drop, and multi-select behavior.
- The Tasks Kanban board supports grouped drag/drop, selection, keyboard-operable column controls, and authoritative refresh. A Command/Ctrl-selected pointer drag puts every selected real card into its own fixed-position motion with a source-slot placeholder, applies the same pointer delta to each, and restores every card's placeholder, styles, and drag state on drop or cancellation; the initially grabbed card remains the drop anchor. Valid pointer drops optimistically insert all moved cards into the actual destination DOM and track pending moves by generation; authoritative board swaps synchronously reapply those moves before paint so cleanup or stale markup cannot flash cards back into the source. Move start aborts any older in-flight SSE board GET while retaining its invalidation, new SSE refreshes stay deferred until all moves settle, and stale mutation responses cannot overwrite newer state. A successful mutation retains each transaction's optimistic placement until an authoritative reconciliation is accepted. Each forced reconciliation snapshots every settled move generation it covers when its GET starts. Its response excludes all covered generations from optimistic projection, commits the server-rendered fragment unchanged, and clears all covered projections only after `htmx:afterSwap`; moves that settle after the snapshot remain projected and require their own reconciliation. Accepted board-request order, rather than nominal reconciliation generation, fences late responses, so concurrent successful moves may reconcile in reverse generation order without leaving either card optimistic. Non-2xx settlement is determined from `htmx:afterRequest` rather than the `htmx.ajax()` promise, clears only the failed optimistic transaction, shows the existing response feedback, and forces an immediate authoritative refresh for rollback. Board-response ordering advances request and reconciliation watermarks only after `htmx:afterSwap`; a later failed, aborted, or later-cancelled refresh therefore cannot reject an earlier valid forced rollback. Final reconciliation is independently pending until its matching authoritative board swap succeeds, retries unsuccessful or aborted attempts, and defers SSE refreshes until completion. Board refresh retains surviving selection/menu focus; navigation clears document-global state; grouped drops snapshot IDs before clearing selection. Merge menus are pre-rendered from authoritative eligibility, and stale branch refs fail closed per card without disabling valid cards. Task kebab rows, including Local/GitHub submenu triggers and nested merge/PR actions, match Automation-card kebabs using standard compact DaisyUI menu sizing; touch-target sizing remains reserved for kebab/delete controls. Task-column sort actions use `whitespace-nowrap`, including active/bold options, so labels do not wrap into rows taller than the shared menu reference. Kebab menus stay invisible and pointer-inert until fixed viewport geometry stabilizes, with keyboard focus queued until reveal. Pointer focus must not open a menu during `mousedown`; click is the sole pointer toggle, while keyboard focus opens normally. Local/GitHub merge submenus use an interactive body-level portal while retaining source ownership for dismissal, keyboard/focus handling, HTMX startup, and action dispatch. Native browser input is required for pointer and keyboard behavior; detailed validation expectations belong in `testing_coverage_and_performance.md`. Failure responses must roll back through an authoritative refresh; newer failed or aborted refreshes cannot reject an earlier valid reconciliation. Backend Active-lane ordering, lifecycle-owned handoffs, and durable execution reservations are canonical in `openvibely_architecture.md` and `chat_thread_system.md`. Explicit user sort modes remain authoritative; synthetic events are supplemental. The board still lacks bounded title/prompt search (`#938`), and Pulse has inconsistent failed-task actions/wording (`#866`).
- Local merge actions use one product-owned `task_worktree_merge_actions` descriptor across Kanban, Worktree, and Changes while each surface retains eligibility, target, and request context. Card-originated stale actions return board-compatible non-success responses; missing/foreign task-card PR requests are indistinguishable. Worktree details and lease rules remain in the worktree topic.
- Kanban task-card merge, fast-forward, rebase, squash, and PR actions execute immediately from the kebab menu without a confirmation dialog or floating progress/status indicator. The direct-action flow keeps one global in-flight request guard, closes the menu on activation, and marks only the board `aria-busy` during the request. It preserves server-side eligibility and mutation revalidation, allows retry after failure, and clears busy/portal state while restoring focus for matching completions, including controlled non-`2xx` responses. Failed responses without a canonical `openvibelyToast` in any HTMX trigger phase receive one generic action-specific client toast keyed by task and action; server-provided toasts and authoritative board responses remain authoritative and suppress the fallback.
- Models, Personalities, Skills, Agents, Alerts, and Channels start with compact projections. Lazy dialogs fetch authorized detail, guard request generations/returned IDs, and disable Save until hydration succeeds. Secret dialogs reset unsaved/revealed values on reopen; project-scoped paths preserve `project_id`. The Agents edit modal currently violates the stale-response guard for lifecycle hydration: open bug `#1160` records that a delayed response for Agent A can overwrite the shared lifecycle form/hooks after the user switches to Agent B, and the save path can persist Agent A's lifecycle metadata into Agent B. The fix needs request-generation plus returned-agent identity checks and a deferred-response rapid-switch/save Chromium regression. Automation YAML editor/read-only panels share line numbers, syntax highlighting, indentation rails, horizontal scrolling, no word wrap/folding, two-space Tab, and Shift+Tab dedent. Theming rules are canonical in `ui_theming.md`.
