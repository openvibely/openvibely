OpenVibely uses server-rendered HTMX/templ UI with shared SSE live updates. Durable UI rule: SSE announces that something changed; HTMX/server-rendered templ fragments remain authoritative state.

Realtime and diff contracts:
- Shared `/events/live` multiplexes task, Chat, mixture-progress, and file-change invalidations. Sidebar JavaScript dispatches `sse-task-event`, `sse-chat-live-event`, `sse-file-change-event`, and `sse-live-connected`.
- Committed Automation claims/failures publish project/task-scoped `task_board_updated`; Tasks performs a scoped/debounced authoritative refresh. Automation Live performs an identity-scoped refresh on `sse-live-connected` because invalidations may be missed while disconnected.
- `window._tabVisibility` owns broad realtime visibility and pauses polling while hidden. Per-execution `/events/chat/:exec_id` is the token stream; SQLite is the durable reconnect source and `events.ExecutionStreamHub` carries hot deltas by exact execution ID, with bounded subscribers, nonblocking slow-consumer drops, and terminal close.
- `internal/events` has one broadcaster core for task, chat, and file-change events. It owns locking, capacity, cleanup, nonblocking publication, and counts; typed wrappers keep public APIs/capacities. Cancellation removes subscribers; capacity failures clean earlier subscriptions and return `503`.
- `llmstream.Writer.Write` publishes cumulative raw UTF-8 byte offsets after unlocking. Seeded/`WriteText` content is not republished and token writes do not synchronously flush SQLite. Periodic/final persistence prevents an older periodic snapshot overwriting a newer terminal flush.
- Execution SSE subscribes before database catch-up, clamps untrusted UTF-8 offsets, skips duplicate/partial overlaps, and performs targeted durable catch-up when deltas drop. Terminal events follow durable terminal writes; completed/cancelled map to `done`, failures to `error`, and missing output is replayed before terminal status.
- File changes are invalidation/snapshot signals. `diff_snapshot` is metadata-only; full diffs remain in database/routes and browsers refresh authoritative Changes fragments. Changes is lazy unless `tab=changes`, and direct and lazy routes must agree. Recoverable merge failures return refreshed fragments with feedback and retry actions; genuine conflicts expose recovery guidance plus Resolve/Abort and hide ordinary merge actions. Kanban task-card Fast-forward operation failures/conflicts likewise return a `200` swap-safe authoritative board refresh with an `openvibelyToast` failure event, while stale eligibility/precondition failures retain controlled non-success responses. Worktree lease/eligibility rules are canonical in `worktree_and_lineage.md`.
- Diff viewers use GitHub-style load envelopes, oversized placeholders, deletion summaries, constrained rename/copy headers, and viewport-safe overflow. `app_settings.ui.diff_view` is `inline` by default, accepts `split`, and normalizes legacy `unified`; only user toggles persist it.

Chat, task-thread, and lifecycle rendering:
- Chat and task-thread streaming batch DOM updates and force a final flush. Chat reconciles its `streaming-message-<exec_id>` node; task-thread appends authoritative execution fragments. Start/input-applied events must not replace a fresh stream with a page reload.
- Terminal reconciliation uses persisted status/output regardless of event arrival order, replaces loading dots, and reconciles composer state. Queued/steering inputs remain compact composer rows, with attachment indicators preserved through refresh/reconnect/live creation. Promoted runs remove pending rows and attach their stream.
- Completed/error bubbles use compact `data-raw-content` and one shared scanner/queue per page or fragment for Markdown/code hydration, sanitization, links, copy, partial failed/cancelled output, pagination, morph swaps, and `hx-preserve`. Tool results retain full fidelity in bounded responsive containers. Browser Task Detail eagerly loads Thread after roughly 100 ms and pages five executions by default; unlike model-facing `view_task_thread`, this path has no byte budget, so multi-megabyte executions can block usability. The durable scanner fix keeps large code-range work asynchronous past the former three-second cutoff, bounded by the owning render deadline; genuine worker failure renders escaped plaintext instead of synchronously rescanning. Matching rendered revisions are skipped only when visible content remains, so blank containers rehydrate. A bounded initial-output projection plus authorized exact-output loading remains proposed rather than implemented.
- Alert inspection lazily reuses the same Markdown/sanitization/code-copy/link pipeline. Exact body bytes are separately Base64-encoded UTF-8 for clipboard decoding immediately before copy, preserving LF, CRLF, and bare CR despite `<pre>` normalization; fallback is escaped inert text.
- Lifecycle activity is project-scoped and prompt-safe, ordered by `(started_at DESC, id DESC)`, and paged with keyset cursors. Refresh/reconnect renders a bounded newest page; retained nonterminal rows can be rehydrated individually, missed older history appears as chronological gap sentinels, and continuations load bounded pages without draining history. Cleanup cancels timers/listeners/requests and invalidates detached callbacks without losing anchors.
- Task-run validation evidence remains a review gap: execution/task-detail data has status but no explicit per-run validation field/projection (`#927`). Lifecycle activity stays separate from the main Thread.

Shared composer and navigation:
- Chat/task-thread composers share `web/templates/components/chat_shared.templ` and `ChatInputForm`. The primary Send button becomes a same-styled square-icon Stop while active; action-only responses use an OOB primary-action fragment. Send controls keep `chat-send-button` in initial and rebuilt markup; Stop does not.
- While running, trimmed text determines send versus queue/steer locally, but server OOB state wins. Submit delegates to the current post-swap button and clears text/session only after acceptance. Deferred steering handles races before an execution ID exists; a lost `409` steer retries once as a normal send. In-flight counters start at `htmx:beforeRequest` so native validation cannot strand them.
- Desktop Chat actions use a semantic button with `aria-expanded` and `data-chat-actions-open`, not a focusable DaisyUI label. Outside activity, focus-out, history restoration, and fragment initialization close it; Escape restores focus. Clear Chat retains exact destructive confirmation. Overlapping action-only refresh stale-response handling remains `#48`.
- Server-rendered `PageTitle` markers own browser titles. Programmatic navigation uses `window.openVibelyNavigate`; history misses request full documents while ordinary HTMX requests remain fragments. Revision no-ops cancel before capturing draft/scroll, cleaning EventSource, or mutating DOM. Final transcript parsing treats LF/CRLF/bare CR equivalently without changing source bytes, escapes raw `<` outside protected code, sanitizes HTML/URLs, and keeps malformed/example controls inert.
- Deep breadcrumb selectors are compact, project-scoped search results. Task, schedule-origin Task, and Automation searches include the currently selected item when its name/title matches the query and preserve its selected marker; the current item is omitted only when it does not match. Clearing the query restores normal current-item visibility and current-first ordering. A Task selector opened with the allowlisted `from=schedule` origin must require live Schedule-calendar membership through an existing schedule row for that task, excluding ordinary unscheduled and foreign-project tasks; a retained `category = 'scheduled'` value alone is stale evidence after a schedule is deleted. Disabled schedule rows remain eligible. Normal Task selectors remain broader. The selector carries the origin separately from the active tab and selected Task destinations preserve both `from=schedule` and the allowlisted tab. Handler, repository, component, and production-shaped Chromium regressions cover the contract.
- Review navigation still lacks visible Thread/Reflection links to execution details (`#365`, `#380`), and hard refresh after cancellation lacks the same explicit terminal marker as completed/failed threads (`#226`).

Cards, pagination, and responsive behavior:
- Card lists use `data-card-search` and `window.refreshCardSearches`. URL search seeds only initial render. Refreshes carry bounded `card_window`, preserve search/window/anchor/focus, and continue from explicit rendered offset. Fixed injected cards can participate in replacement focus/anchor snapshots without affecting page counts, offsets, appends, or deduplication. Pagination completion is silent: hide sentinel/status when `hasMore=false` and retain transient loading/error/retry hooks without an end marker.
- Shared collection-card toolbars use a checkbox master control for currently loaded eligible cards rather than a text `Select loaded` action. The master reflects checked/indeterminate state, query changes clear selection, and fixed ineligible cards receive disabled checkboxes with accessible explanations while eligible dynamic cards remain selectable. Selection mode keeps the master checkbox and search mounted, replacing only Filters/Sort with contextual actions; unchecking the master clears selection and restores those query controls. Filter popovers use explicit `aria-expanded` and class-driven state, so a second trigger click, outside click, or Escape dismisses them; injected selection gutters are title-aligned and reinitialized after HTMX swaps. On desktop, toolbar-owned card roots reserve the 32 px selection gutter in initial CSS before paint, excluding empty-state cards; the installer injects and aligns the checkbox without adding post-paint card padding, preventing title movement on initial load and server-backed search replacement.
- Shared card-root refreshes through `refreshCollection()` reinitialize the replacement toolbar after manual root replacement, preserving master-checkbox, filter, and bulk-action behavior for Alerts and other collection-card pages.
- HTMX/root replacement aborts requests, clears timers/observers/listeners, and snapshots/restores search, viewport, anchor, and focus. Focus restoration rejects hidden/inert/disabled/aria-disabled targets, avoids reopening menus, and falls back to a visible adjacent card or search input. Channels keeps fixed provider/Outbound Target cards in the root while webhook pagination remains scoped to `#webhook-card-list`; configured GitHub, Slack, Telegram, Discord, X, and Email cards are eligible for shared selection/removal, while Outbound Target cards remain ineligible. Bulk removal submits all selected provider and webhook IDs to one `/channels/bulk` request; server-side preflight and the atomic transaction prevent partial deletion, and the UI refreshes authoritative state only after success.
- Channels preserves `data-search-card` on its empty-state placeholder while shared selection excludes empty states from checkbox/control injection, so empty cards receive no selection padding.
- Sidebar collapse and Ctrl/Cmd+B use one helper for DOM/accessibility state, localStorage mirror, and background `/ui/preferences` persistence. Full documents embed early state; fragments do not fetch preferences. Sidebar selection is hover-only, not DaisyUI `.active`.
- The shared project switcher keeps `#project-selector` as the compact identity-only select with its established collapsed `select select-bordered select-sm w-full sidebar-project-select` visual styling and existing change/persistence path, while exposing an accessible searchable dialog. The collapsed trigger retains the built-in DaisyUI select arrow; do not replace it with a custom caret SVG or `bg-none`. Project and Task/Automation breadcrumb selectors use one neutral `SearchableSelector` templ component and one shared browser controller for the dialog shell, direct-child panel, search/results controls, opening, closing, positioning, filtering/search events, clearing, keyboard traversal, result selection, and HTMX/history lifecycle handling. Shared selector popups have no header or close button: the inset search box is first, followed directly by available results. Give the dialog a direct accessible label such as `Select Task`; Escape and backdrop clicks remain the supported dismissal paths. Do not reintroduce project- or breadcrumb-specific copies of that shell or controller. Data-specific behavior remains configurable: project options filter locally and dispatch the existing hidden-select change event, while breadcrumb results load through HTMX and navigate by URL. Local project search includes the currently selected project when its name matches and preserves its check/`aria-selected` marker; it hides the current project only when the query does not match, and clearing the query restores every project and normal current markers/order. Local project filtering uses only the inline direct `input` and native `search` hooks exposed by the shared component; do not add delegated local filtering listeners, because that duplicates synchronous option scans and positioning for every event. Local filtering must set the option `hidden` property and toggle the Tailwind `hidden` utility class because each option also has `display:flex`, which can otherwise leave a nonmatch painted. Both modes use plain `type="text"` search inputs so browsers do not render a native X, and neither mode adds a custom clear control; users clear queries through ordinary text editing, whose `input` event restores unfiltered results. Their option rows intentionally match Automation-card kebab items with compact `px-4 py-2` geometry and `bg-base-content/10` hover highlighting; do not restore selector-specific `min-h-11`, narrower `px-3`, or `hover:bg-base-200`. Their search controls likewise match the Automations collection search: an inset `p-2` area containing the rounded, bordered `card border border-base-300 bg-base-100 shadow-sm` shell and its borderless `px-4 py-2` input, so the search border never touches the popup border. Shared class constants remain in `web/templates/searchable_selector_styles.go`; the reusable shell/controller lives in `web/templates/searchable_selector.templ`. The project dialog must not add a project-only DaisyUI `.modal-box` wrapper or `.ov-modal-close` styling layer. Project options use the breadcrumb check-column treatment and `role="option"` plus `aria-selected`, not a project-only `Current` badge or `aria-current` (reserved by sidebar navigation tests). The dialog uses fixed viewport positioning attached to the trigger, with the trigger's left edge as the preferred project-popup anchor; horizontal clamping, upward fallback, and scroll/resize repositioning handle constrained viewports. The shared controller resolves live nodes on every event so full-page, HTMX, and direct DOM replacements cannot leave stale cached controls. The shared controller owns document/window listeners through a stored `AbortController`; reinstalling it tears down older listeners to prevent duplicated filtering and positioning. Selection preserves unsaved-change confirmation, same-page-family routing with `project_id`, `window.openVibelyNavigate`, default-first ordering, and empty-workspace fallback. The panel inherits the dialog's dynamic maximum height and remains overflow-hidden, leaving the results pane as the sole vertical scroll owner.
- Clipboard uses `window.openVibelyCopyText`; toasts use `openvibelyToast`, account for native-dialog top layers/mobile insets, and deduplicate Automation-start notices by neutral `toast_key`. Worktree success paths preserve unrelated HTMX trigger keys.
- Destructive deletes use one accessible DaisyUI `<dialog>` pattern. Task-board Delete All is page-scoped with allowlisted category/project inputs, duplicate-submit protection, retry, and authoritative refresh. Cancel/Escape restore the invoker or visible kebab; confirmed deletion deliberately suppresses invoker restoration so a closing dialog cannot reopen a menu.
- Chat/thread panes, cards, badges, composers, and tool output use `min-w-0` and bounded inner overflow without clipping roots/shadows/tails. Mobile controls truncate selectors while action clusters remain intact. Task Detail tabs are Prompt, Goal, Git Worktree, followed by the remaining tabs in a horizontally scrollable row.
- Task state icons are server-rendered from authoritative projections and remain accessible/shrink-safe. `GoalMet` is derived only for completed tasks with an achieved persisted goal; merged status has precedence and goal never masks running, failed, cancelled, blocked, or other non-completed states. The board derives it with SQL `EXISTS`; the documented SVG in `docs/task-status-icon-options.html` is canonical. Failed/cancelled rows are excluded from active dropzones.
- Task Details Changes surfaces stay contained at 320px. The Lifecycle card uses a full-height flex/min-height chain and an activity-owned scrollport; explanatory text must not be a direct `.card-body > p` flex-growing child. Completed Threads show Changes, warranted merge guidance, or no-diff/no-output guidance. The board uses one/two/three columns across phone/tablet/desktop and places `+ Add Task` beside the title.
- The Tasks Kanban board supports grouped drag/drop, selection, keyboard-operable column controls, and authoritative refresh. Valid pointer drops optimistically insert all moved cards into the actual destination DOM and track pending moves by generation; authoritative board swaps synchronously reapply those moves before paint so cleanup or stale markup cannot flash cards back into the source. Move start aborts any older in-flight SSE board GET while retaining its invalidation, new SSE refreshes stay deferred until all moves settle, and stale mutation responses cannot overwrite newer state. Successful mutation settlement reconciles server-rendered ordering and counts; non-2xx settlement is determined from `htmx:afterRequest` rather than the `htmx.ajax()` promise, clears only the failed optimistic transaction, shows the existing response feedback, and forces an immediate authoritative refresh for rollback. Board refresh retains surviving selection/menu focus; navigation clears document-global state; grouped drops snapshot IDs before clearing selection. Merge menus are pre-rendered from authoritative eligibility, and stale branch refs fail closed per card without disabling valid cards. Task kebab rows, including Local/GitHub submenu triggers and nested merge/PR actions, match Automation-card kebabs using standard compact DaisyUI menu sizing; touch-target sizing remains reserved for kebab/delete controls. Task-column sort actions use `whitespace-nowrap`, including active/bold options, so labels do not wrap into rows taller than the shared menu reference. Kebab menus stay invisible and pointer-inert until fixed viewport geometry stabilizes, with keyboard focus queued until reveal. Pointer focus must not open a menu during `mousedown`; click is the sole pointer toggle, while keyboard focus opens normally. Local/GitHub merge submenus use an interactive body-level portal while retaining source ownership for dismissal, keyboard/focus handling, HTMX startup, and action dispatch. Native browser input is required for pointer and keyboard regressions; Kanban pending-move coverage holds persistence open, injects SSE invalidation, observes intermediate frames for source-column rollback, and verifies both authoritative success and failure rollback. Synthetic events are supplemental. The board still lacks bounded title/prompt search (`#938`), and Pulse has inconsistent failed-task actions/wording (`#866`).
- Local merge actions use one product-owned `task_worktree_merge_actions` descriptor across Kanban, Worktree, and Changes while each surface retains eligibility, target, and request context. Card-originated stale actions return board-compatible non-success responses; missing/foreign task-card PR requests are indistinguishable. Worktree details and lease rules remain in the worktree topic.
- Kanban task-card merge, fast-forward, rebase, squash, and PR actions execute immediately from the kebab menu without a confirmation dialog. The direct-action flow keeps one global in-flight request guard, closes the menu on activation, and displays a persistent action-named spinner/status alert while marking the board `aria-busy`. It preserves server-side eligibility and mutation revalidation, allows retry after failure, and clears busy/portal state while restoring focus for matching completions, including controlled non-`2xx` responses. Failed responses without a canonical `openvibelyToast` in any HTMX trigger phase receive one generic action-specific client toast keyed by task and action; server-provided toasts and authoritative board responses remain authoritative and suppress the fallback. Production-shaped Chromium coverage verifies a bare `409` still provides visible feedback while preserving duplicate-request blocking, cleanup, focus restoration, and retry.
- Models, Personalities, Skills, Agents, Alerts, and Channels start with compact projections. Lazy dialogs fetch authorized detail, guard request generations/returned IDs, and disable Save until hydration succeeds. Secret dialogs reset unsaved/revealed values on reopen; project-scoped paths preserve `project_id`. Automation YAML editor/read-only panels share line numbers, syntax highlighting, indentation rails, horizontal scrolling, no word wrap/folding, two-space Tab, and Shift+Tab dedent. Theming rules are canonical in `ui_theming.md`.
