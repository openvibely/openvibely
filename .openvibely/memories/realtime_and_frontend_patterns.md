OpenVibely uses server-rendered HTMX/templ UI with shared SSE-style live updates. Durable UI contract: SSE announces that something changed, while HTMX/server-rendered templ fragments remain authoritative state.

Realtime and diff contracts:
- Shared `/events/live` multiplexes task, chat, mixture-progress, and file-change invalidations. Sidebar-managed JavaScript dispatches `sse-task-event`, `sse-chat-live-event`, `sse-file-change-event`, and `sse-live-connected`.
- Committed Automation claims and failures publish project/task-scoped `task_board_updated`; the production shared-SSE route forwards it and the Tasks page performs a scoped/debounced authoritative refresh. This path is required for reservation-backed `AutomationCapacityQueued` visibility and must not rely only on status/category changes.
- Automation Live performs an identity-scoped authoritative refresh immediately on shared `sse-live-connected`, because invalidations can be missed while the connection is down. On 2026-08-30, the reconnect coverage was made production-shaped in `internal/handler/automation_capacity_live_browser_test.go`: the test renders the full `pages.AutomationLive` document, uses the real `Handler.LiveEventsSSE` route and shared sidebar coordinator, cancels the first server-side stream, requires a second native EventSource connection, and verifies the real reconnect `onopen` dispatch refreshes a stale failed snapshot to running through the existing project/Automation-scoped generation guards. Existing Run now, delayed-response, refresh, reload, isolation, and terminal-failure checks remain. No application implementation change was needed; focused Chromium coverage, `go build ./...`, `go vet ./...`, uncached `go test ./internal/... ./web/... -count=1 -timeout 240s`, and `git diff --check` passed. A separate fresh strict read-only audit found no material bugs, regressions, or missing requirements and made no workspace changes.
- `window._tabVisibility` owns broad realtime visibility behavior and pauses polling while hidden.
- Per-execution `/events/chat/:exec_id` streams are the token-output path. SQLite is the durable transcript/reconnect source; hot deltas use the injected `events.ExecutionStreamHub`, which is keyed by exact execution ID, supports multiple subscribers, bounds subscribers, drops slow deltas nonblockingly, and closes on terminal events.
- `internal/events` shares one generic broadcaster core for task, chat, and file-change broadcasters. It owns subscriber locking, capacity, idempotent cleanup, nonblocking publication, and counts; typed wrappers retain their public APIs and capacities. Cancellation must remove subscribers, and capacity failures return `503` after cleaning earlier subscriptions.
- `llmstream.Writer.Write` publishes cumulative raw UTF-8 byte offsets after releasing its mutex. Seeded output and `WriteText` content are not republished, and the token path does not synchronously flush SQLite. Periodic/final persistence serializes snapshots so an older periodic write cannot overwrite a newer final flush.
- Per-execution SSE subscribes before database catch-up, clamps untrusted UTF-8 offsets, skips duplicate/partial overlaps, and uses targeted durable catch-up for dropped deltas or terminal fallback. Terminal events publish only after durable terminal writes; completed/cancelled map to `done`, failures to `error`, and terminal handlers replay missing output first.
- File changes are invalidation/snapshot signals. `diff_snapshot` is metadata-only; full diffs remain in database/routes and browsers refresh authoritative Changes fragments. Changes is lazy unless `tab=changes`, and direct `?tab=changes` must match the lazy route. Changes-tab merge failures that remain recoverable must return a freshly rendered authoritative fragment with failure feedback rather than plain error text, preserving retry actions; conflict fragments expose recovery guidance and Resolve/Abort without ordinary merge actions. All submitted action-menu controls disable together until the request settles. `WorktreeService` uses one process-wide lease keyed by the canonical Git common directory after absolute-path and symlink resolution, so merge and rebase mutations coordinate across aliases, linked worktrees, and separate service instances. Merge and Rebase handler requests revalidate live task/Git eligibility and ancestry, with Rebase also requiring actual two-sided divergence, immediately before mutation under that lease. The service parses staged and conflict paths from exact NUL-delimited Git output, preserving valid whitespace/newline filenames during squash commits and conflict recovery. Changes-tab merge failures that leave the branch/worktree recoverable reload authoritative task/Git state and return a refreshed Changes fragment with failure feedback; genuine conflicts expose Resolve/Abort recovery controls while ordinary merge actions stay hidden. Legacy no-`MERGE_HEAD` Abort uses task-scoped path restoration while preserving unrelated staged work. Live Git reconciliation clears stale persisted conflict state only when no active merge or unmerged files remain, while recovery is exposed only for the task that owns the active merge. Chat, task-thread, and lifecycle rendering:
- Chat and task-thread streaming batches DOM rendering and forces a final flush. Chat completion reconciles the inner `streaming-message-<exec_id>` node, while task-thread starts append authoritative server-rendered execution fragments. Start/input-applied listeners must not replace fresh streams with a page-level thread reload.
- Terminal reconciliation uses persisted status/output regardless of whether shared completion or per-execution terminal arrives first, and must replace loading dots with the assistant result while reconciling composer state.
- Queued and steering-pending inputs render as compact composer rows, not transcript bubbles. Attachment indicators remain consistent across fragments, refresh, reconnect, and live-created rows. Queued attachment events stay on the queued-row path; queued-to-steering conversion publishes a cross-tab steering event and guards the same-tab swap until the response settles.
- Promoted queued task-thread runs remove pending rows, append execution fragments, and attach streams from live events. Either execution-started or input-applied is sufficient for recovery, and all pending/live selectors are task-qualified.
- Initial Task Run publishes `task_thread_execution_started` after the execution row exists. Stale visible-task responses must not replace a composer containing active pending uploads.
- Long histories remain complete in SQLite but are UI-windowed with scroll-top pagination, initially 30 rows and at most 100. Browser-memory protection removes old execution DOM nodes. Active streaming follows growth only while the viewer is pinned; upward movement is user intent.
- Completed/error bubbles use compact `data-raw-content` markup and one shared scanner/queue per page or HTMX fragment, preserving Markdown/code hydration, task links, copy buttons, partial failed/cancelled output, pagination, morph swaps, running resume, and `hx-preserve`. Tool results remain full fidelity in responsive scroll containers.
- Lazily hydrated Alert inspection uses the same shared Markdown, sanitization, code-copy, and link-behavior pipeline as Chat/task-thread content; it carries a separate Base64-encoded UTF-8 raw-body source for copying and decodes it immediately before clipboard write, preserving LF, CRLF, and bare-CR bytes despite HTML `<pre>` normalization. It uses escaped inert text when shared Markdown setup or parsing fails.
- Lifecycle activity is project-scoped and prompt-safe. The tab uses deterministic newest-first `(started_at DESC, id DESC)` ordering, keyset `before`/`after` pagination, and durable lifecycle-change events. Full refresh/reconnect renders the newest bounded page immediately; retained nonterminal rows can be rehydrated by compact single-execution lookup, and missed older history is represented by chronological gap sentinels. Each user-driven continuation loads one bounded page, deduplicates and clips at known-row overlap, preserves anchors, retries failures, and never eagerly drains an unbounded history. Cleanup cancels timers/listeners/requests and invalidates detached callbacks without losing saved scroll/anchor state.
- Known lifecycle evidence gaps are richer prompt-safe trace detail and richer selected-memory context; lifecycle activity must remain separate from the main Thread.
- Task-run validation is a separate review-evidence gap: the current execution schema/task-detail path has status but no explicit validation field or rendered per-run validation projection, while history cards expose timestamps, resource counts, output, and errors. GitHub suggestion `#927` tracks a read-only projection that places explicit validation evidence beside reviewable task changes and distinguishes missing evidence from a pass; it is not a proposal for a new test runner or merge gate.

Shared composer and navigation:
- Chat and task-thread composers share `web/templates/components/chat_shared.templ` and one `ChatInputForm` contract. The active primary button becomes a same-styled Stop with a square icon; action-only responses use an OOB primary-action fragment. Send controls carry the `chat-send-button` class in both initial markup and JavaScript-rebuilt markup so shared theme rules survive Send/Stop swaps; Stop controls must not carry that class.
- While running, trimmed text determines Send versus queue/steer locally, while server OOB state remains authoritative. Submit delegates to the current post-swap button, clears text/session only after accepted submission, preserves explicitly cleared attachments, and captures deferred steering until a new execution ID appears. A lost `409` steer race retries once as normal send; in-flight counters begin at `htmx:beforeRequest` so native validation cannot strand them.
- Hints are platform-aware: Apple uses `⏎ sends or queues · ⌘+⏎ steers`, other platforms use `Enter sends or queues · Ctrl+Enter steers`; Shift+Enter inserts a newline. Portal model/mode selectors append to `document.body` with hidden inputs.
- Desktop Chat actions use a semantic button with `aria-expanded` and explicit `data-chat-actions-open`, not a focusable DaisyUI label. CSS must enforce closed/open states; outside activity, focus-out, history restoration, and fragment initialization close it, while Escape restores focus. Clear Chat retains its exact destructive confirmation. Known race `#48` is stale-response handling for overlapping action-only refreshes.
- Browser titles come from server-rendered `PageTitle` markers. Programmatic navigation uses `window.openVibelyNavigate`; HTMX history cache misses request full documents, while ordinary HTMX requests remain fragments. Revision no-ops cancel before draft/scroll capture, EventSource cleanup, or DOM mutation; forced task refreshes close per-execution EventSources only after that check.
- Final transcript rendering treats LF, CRLF, and bare CR equivalently without changing source bytes. Shared parsing escapes raw `<` outside protected multiline/unmatched code ranges, sanitizes dangerous HTML/URLs, and keeps malformed or example control markers visible/inert. Safe external links leave the app view; internal links use normal navigation.
- Known review-navigation gaps are missing visible Thread/Reflection links to execution-detail pages (`#365`, `#380`), and hard refresh after cancellation does not show the same explicit terminal marker as completed/failed threads (`#226`).
