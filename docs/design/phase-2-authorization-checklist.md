# Phase 2 authorization verification checklist

The unreleased Phase 2 database changes are consolidated in `224_project_authorization.sql`, upgrading directly from version 223. Tests cover upgrade, rollback, and re-upgrade from that released boundary. Rollback removes the Phase 2 schema while preserving existing source records; no external-user bindings are inferred. Migration 225 makes Telegram/Slack/Discord/email sender mappings global, preserves unambiguous bindings, and flags unresolved entries for review. Earlier incremental Phase 2 migrations are consolidated; main’s migrations through 223 are preserved.

Every surface below now has production wiring and tests; the last column lists known limitations. Private projects remain disabled until Phase 3 sandboxing. Evidence for individual changes is recorded in [historical checkpoints](teams-orgs-history.md). A surface closes only after its production wiring, role boundaries, cross-project behavior, revocation, auth-off behavior, and relevant tests are verified.

## Scope and limitations

This checklist describes current application authorization, not process or
filesystem isolation. See [Current status](teams-orgs.md#current-status) for the
consolidated remaining work. Browser coverage includes the sharing panel; it does
not imply every feature has an end-to-end browser test. The old checkpoint log is
preserved in the [historical archive](teams-orgs-history.md#archived-verification-checklist-checkpoints),
where “unfinished” and superseded watcher behavior describe historical stages.
