can we check how Gemini OAuth prompt configuration works compared to API-key connections?

I checked the OAuth bootstrap path and the prompt assembly pipeline in internal/agent/gemini. The OAuth endpoint returns per-model prompt overrides alongside the active quota tier, while API-key connections use the static bundled prompt templates.

internal/agent/gemini/prompt_overrides.go Go 
func (r *OverrideResolver) ResolvePrompt(ctx context.Context, model string) (PromptBundle, error) {
    // Prefer fresh per-model OAuth overrides; fall back cleanly to bundled defaults.
    if cached, ok := r.cache.Get(model); ok && !cached.Expired() {
        return r.mergeWithBundled(cached.Overrides), nil
    }
    return r.bundled.ForModel(model), nil
}

No live configuration fetching needed—the verified prompts will be bundled locally.
