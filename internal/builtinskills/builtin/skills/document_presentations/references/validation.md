## Explicit final checks

Before delivery, run `"$PAPERWORKS" verify-slides FINAL.pptx --requirements requirements.json` on the final saved file. Declare only actual task requirements. Example: `{"slides":2,"size_emu":[12191695,6858000],"native_tables":[1],"native_charts":[1],"fonts":["Arial"],"table_sums":[{"slide":1,"table":1,"inputs":[[1,1],[2,1]],"total":[3,1],"tolerance":0.01}]}`. Slide/table indices start at one; cell row/column indices start at zero. Include the cover in the total unless explicitly requested separately. Omit inapplicable fields. Choose tolerances from units and rounding; do not infer a sum from an ambiguous label. Checks reject broken relationships, missing requested native objects, explicit-font mismatches, incorrect declared sums and chart reference caches that disagree with the saved embedded workbook. They do not prove font inheritance, text fit or preservation of the original workbook formulas. Cached formulas without saved results require recalculation before validation.

Independently check ratios, percentage conversions (0.31 means 31%) and mixed-unit arithmetic; declared table sums do not cover them. For chart edits, compare categories, series order, cached values, source formulas and embedded workbook cells. Preserve the original workbook when lineage is required; snapshots need explicit intent. Update dependent percentages, titles, table values and notes. For narrow package edits use the helper's `verify-preservation` operation with explicitly allowed part paths, then visually compare slides.

Verify font availability and glyph coverage for chosen designs as well as supplied references. When fonts are required by the design, user or a supplied reference, include `"fonts": ["Required family"], "render_fonts": true` in the `verify-slides` requirements. This renders a temporary copy and checks the font families actually used, including inherited and chart text. A saved font name alone is insufficient. Include symbol or additional-script families only when appropriate to the actual design. A substituted or unidentifiable font fails; install the required font through the permitted environment or report the limitation. Inspect the rendered slides as well. This verifies the current rendering runtime, not font availability on the recipient's machine.

The same check rejects reported off-slide geometry, the placeholder chart title `Chart Title`, malformed literal chart points, missing chart workbooks, invalid explicit bullet indents, and measured heading overflow. It reports headings whose inherited/unavailable font metrics still need rendered inspection.

Literal-only charts need an explicit delivery choice. For a user-requested PowerPoint-only output, pass `"target_application":"powerpoint"` in the requirements; literal values are validated and reported separately from workbook references. For a new snapshot that should have editable workbook data, explicitly run `"$PAPERWORKS" materialize-charts draft.pptx --output with-workbooks.pptx`, then `verify-slides`, render and inspect. Materialization preserves literal values and chart styling; it does not recover source formulas or links. It refuses charts that already have workbook references, rather than replacing their lineage.


## Paired previews and native layout reports

Use `"$PAPERWORKS" slide-preview input.pptx --output new-preview-dir` when you need an image and matching native object metadata. It returns one `slide-N.png` / `slide-N.layout.json` pair per slide. It requires LibreOffice; a page-count mismatch fails without publishing the directory. Existing preview directories may contain regular files only. Use `--slides 1,3` to update selected one-based slide pairs while retaining the others. Without `--slides`, the complete preview set is replaced and obsolete pairs are removed. Unrelated regular files are retained. Rendering still uses the full deck; selection controls which pairs are published.

Read each report alongside its image. Positions use logical 96-DPI pixels; divide by 96 for Paperworks editing inches. The PNG's actual dimensions are in `preview`. Slide-owned records supply `edit_target` with the one-based slide and native `shape_id`. Inherited master/layout objects are marked `editable:false`; they are source-layer records, not additional visible objects or slide-owned edit targets.

Reports resolve local/placeholder geometry and cascading text properties, including Latin theme fonts. Image records expose crop fractions, native stretch/tile fit settings and preset/custom masks. Table records expose cell text, table/cell IDs, spans, merge flags, row/column sizes, and structured paragraph/run, border, fill and margin properties. Local text defaults and embedded conditional table-style regions are applied. The report identifies missing style definitions; application-provided styles absent from the package and renderer defaults remain unresolved. Font sizes retain OOXML hundredths of a point and margins retain EMUs; report cell indices are one-based and are not CLI edit indices. Structured fills resolve placeholder inheritance, theme fill references and color mappings; Common tint/shade, opacity, RGB-channel and HSL transforms resolve in order; unsupported transforms remain explicitly unresolved. Native XML retains detailed formatting and inherited layers. Grouped objects expose slide-space bounds/corners and separate local edit coordinates; use local coordinates for edits. Inherited/theme effect lists expose shadow/glow colors and blur, soft-edge and reflection parameters. These do not provide raster-effect bounds. Renderer font substitutions, effect graphs and unsupported effects remain unresolved; read the report's limitations and inspect PNGs instead of treating missing properties as defaults.
